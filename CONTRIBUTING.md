# Contributing

Thank you for improving `dfir-cedarpelta-analysis`.

This project is a DFIR investigation methodology skill. Contributions should improve evidence handling, analyst reasoning, artifact coverage, parser guidance, output quality, or public usability.

## Contribution Principles

- Keep guidance evidence-driven.
- Separate facts, inferences, limitations, and follow-up actions.
- Do not encourage unsupported compromise or clean-host conclusions.
- Treat missing artifacts as analysis constraints, not proof of absence.
- Avoid vendor-, customer-, or case-specific assumptions unless clearly labeled as examples.
- Do not include real sensitive data, customer names, hostnames, usernames, IP addresses, hashes, or internal paths without explicit approval.

## Useful Contributions

- Cedarpelta artifact coverage notes
- Windows artifact interpretation guidance
- Cross-check rules
- Hunting scenario improvements
- Hypothesis lifecycle refinements
- Pivot examples
- Parser/tool readiness guidance
- JSON schema improvements
- Report template improvements

## Review Checklist

Before opening a pull request:

- Confirm all referenced files exist.
- Check that examples are synthetic or safe to publish.
- Validate JSON files after editing schemas.
- Keep terminology consistent with `SKILL.md` and the SOP.
- Explain what investigation problem the change solves.
